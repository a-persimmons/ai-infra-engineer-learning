# 行为准则

## 我们的承诺

作为成员、贡献者和领导者，我们承诺为所有人提供免受骚扰的社区参与体验，不因年龄、体型、可见或不可见的残障、族裔、性别特征、性别认同及表达、经验水平、教育程度、社会经济地位、国籍、个人外貌、种族、宗教、性身份或性取向而有所区别。

我们承诺以有助于建立开放、友好、多元、包容且健康的社区的方式行动与交流。

## 我们的标准

### 积极行为

有助于营造良好环境的行为示例：

- **尊重他人**：尊重并体谅每个人。
- **友好接纳**：欢迎新成员，帮助他们入门。
- **协作**：共同工作并分享知识。
- **耐心**：每个人都有自己的学习节奏。
- **建设性**：提供有帮助、可执行的反馈。
- **同理心**：理解不同的观点及经历。
- **专业**：在所有交流中保持专业。
- **认可贡献**：承认他人的贡献与想法。

### 不可接受的行为

- **骚扰**：任何形式的骚扰、恐吓或霸凌。
- **歧视**：歧视性笑话、语言或行为。
- **人身攻击**：攻击个人而非讨论观点。
- **恶意挑衅**：故意发表煽动性或偏离主题的评论。
- **侵犯隐私**：未经许可分享他人的私人信息。
- **性相关内容**：不受欢迎的性关注或示好。
- **垃圾信息**：过度自我推广或无关内容。
- **不诚实**：抄袭、冒充或其他欺骗行为。

## 我们的责任

### 维护者

项目维护者负责：
- 澄清并执行可接受行为的标准。
- 采取适当、公平的纠正措施。
- 删除、编辑或拒绝违反本准则的贡献。
- 在适当情况下说明管理决定的理由。

### 社区成员

社区成员应当：
- 阅读并遵守本准则。
- 向维护者报告违规行为。
- 支持友好、包容的环境。
- 得体地接受建设性反馈。
- 关注最有利于社区的事情。

## 适用范围

本准则适用于：
- 所有项目空间（仓库、Issue、Discussion、Pull Request）。
- 官方交流渠道（Slack、邮件列表）。
- 线上或线下活动及聚会。
- 代表项目时使用的社交媒体。
- 其他社区互动。

在公共空间代表本项目时，同样适用。

## 执行

### 举报违规行为

如果你遭遇或目睹不可接受的行为：

1. **向维护者报告**：发送邮件至 conduct@ai-infra-learning.org，或提交保密 Issue。
2. **提供详情**：说明发生了什么、时间、地点及涉及人员。
3. **具体说明**：如有可能，附上链接、截图或其他证据。
4. **保持保密**：举报将得到谨慎处理。

### 举报内容

- 你的联系方式。
- 涉及人员姓名。
- 事件描述。
- 日期与时间。
- 背景与具体情况。
- 支持性证据。
- 其他相关信息。

### 执行流程

1. **审查**：维护者审查举报。
2. **调查**：必要时收集补充信息。
3. **决定**：确定适当的应对措施。
4. **行动**：落实相应处理结果。
5. **跟进**：监测是否再次违规。

### 处理结果

违规可能导致：

**1. 警告**
- 措施：私下书面警告。
- 适用：首次轻微违规。
- 期限：记入记录。

**2. 临时封禁**
- 措施：暂时停止社区参与资格。
- 适用：反复轻微违规或单次中等程度违规。
- 期限：7 天至 3 个月。

**3. 永久封禁**
- 措施：永久取消社区参与资格。
- 适用：严重违规或警告后反复违规。
- 期限：无限期。

### 申诉

若不同意处理决定：
1. 在 7 天内发送邮件至 appeals@ai-infra-learning.org。
2. 解释认为决定不正确的原因。
3. 维护者将在 14 天内审查并回复。
4. 申诉决定为最终决定。

## 具体场景

### Discussion 与 Issue

**建议：**
- 清楚提问并提供背景。
- 发帖前搜索已有讨论。
- 感谢提供帮助的人。
- 问题解决后标记解答。
- 使用合适的标签。

**避免：**
- 要求立即回复。
- 重复发布相同问题。
- 偏离主题。
- 循环争论。
- 使用全大写字母（缩写除外）。

### Pull Request

**建议：**
- 清楚描述变更。
- 建设性地回应反馈。
- 提交前测试代码。
- 遵循贡献指南。
- 耐心等待审查。

**避免：**
- 将代码批评视为人身批评。
- 提交不完整或未测试的代码。
- 忽略审查反馈。
- 未经讨论进行大规模变更。
- 围绕个人风格偏好争论（遵循项目标准）。

### 代码审查

**建议：**
- 聚焦代码，而非个人。
- 解释建议背后的原因。
- 认可良好的工作成果。
- 通过提问沟通，而非发号施令。
- 提出替代方案。

**避免：**
- 使用苛刻或评判性的语言。
- 不加解释地否定他人的顾虑。
- 因轻微风格问题阻止 PR。
- 无理由要求变更。
- 审查自己的代码（利益冲突）。

### 寻求帮助时

**建议：**
- 先搜索文档。
- 提供最小可复现示例。
- 附上错误信息与日志。
- 说明运行环境。
- 展示已尝试的方法。

**避免：**
- 期望别人代替自己完成工作。
- 对帮助者失去耐心。
- 忽略后续问题。
- 在多个渠道重复发帖。
- 直接提醒维护者（使用公共渠道）。

### 帮助他人时

**建议：**
- 对初学者保持耐心。
- 提供解释，而不只是答案。
- 指向相关文档。
- 鼓励学习。
- 认可进步。

**避免：**
- 让他人觉得自己愚蠢。
- 说「自己去 Google 搜」。
- 只提供解答而不解释。
- 根据知识水平设置参与门槛。
- 不必要地使用专业术语。

## 包容性语言

### 推荐用语

- 英文中不清楚性别时使用 they/them。
- 使用 allowlist/denylist，而非 whitelist/blacklist。
- 使用 primary/replica，而非 master/slave。
- 使用 folks 或 everyone，而非 guys。
- 使用以人为先的语言，如 person with disability，而非 disabled person。

### 避免

- 带有性别假设的语言（如假定所有人都是男性）。
- 对残障者不友好的语言（如 crazy、lame、blind spot）。
- 暴力隐喻（如将 kill the process 改为 stop the process）。
- 文化假设（并非所有人都庆祝相同节日）。
- 难以翻译的习语。

## 冲突解决

### 出现分歧时

1. **假设对方有善意**：许多冲突源于误解。
2. **直接沟通**：先私下与对方交流。
3. **聚焦问题**：批评想法，而非个人。
4. **寻求理解**：判断前先提问。
5. **寻找共同点**：发现一致意见。
6. **妥协**：愿意寻求折中方案。
7. **引入调解者**：直接沟通无效时寻求调解。

### 自己犯错时

1. **承认错误**。
2. **真诚道歉**。
3. **补救**：修复造成的伤害。
4. **从中学习**：避免重犯。
5. **继续前进**：无需过度纠结。

### 他人犯错时

1. **给予善意理解**：先假设并非故意。
2. **友善解释**：说明问题所在。
3. **接受道歉**：不要心怀怨恨。
4. **以身作则**：展示适当的行为方式。
5. **继续前进**：关注改进，而非惩罚。

## 创建包容性环境

### 面向初学者

- 提供适合初学者的文档。
- 为新成员标记 good first issue。
- 提供指导机会。
- 认可首次贡献。
- 耐心对待基础问题。

### 面向多元背景的贡献者

- 使用包容性语言。
- 留意时区差异。
- 适应不同沟通方式。
- 认识文化差异。
- 提供多种贡献方式。

### 面向所有人

- 鼓励各种背景的人参与。
- 让代表性不足的人群获得更多表达机会。
- 发现偏见时提出质疑。
- 营造安全的讨论空间。
- 认可多样化的贡献。
