# 项目考核评分标准

本评分标准适用于三个项目的提交评估。

---

## 总体评分等级

| 等级 | 百分比 | 描述 |
|---|---|---|
| **A+** | 95–100% | 卓越——超出全部要求，完成度高 |
| **A** | 90–94% | 优秀——高质量满足全部要求 |
| **B** | 80–89% | 良好——满足大部分要求 |
| **C** | 70–79% | 合格——满足核心要求 |
| **D** | 60–69% | 需要改进——缺少关键组件 |
| **F** | 低于 60% | 不合格——缺少主要组件 |

---

## 考核类别

### 1. 功能性（30 分）

| 标准 | 优秀（27–30） | 良好（24–26） | 合格（21–23） | 需改进（低于 21） |
|---|---|---|---|---|
| **核心功能** | 全部功能正常 | 大部分正常 | 核心功能正常 | 多个功能故障 |
| **需求满足** | 100% | 90% 以上 | 70–89% | 低于 70% |
| **错误处理** | 全面 | 良好 | 基础 | 较差或无 |
| **集成** | 全部组件已集成 | 大部分集成 | 部分集成 | 集成较差 |

**评估问题：**
- 必需端点与功能是否正常？
- 边界情况处理是否正确？
- 系统能否端到端运行？
- 集成是否正常？

---

### 2. 代码质量（25 分）

| 标准 | 优秀（23–25） | 良好（20–22） | 合格（18–19） | 需改进（低于 18） |
|---|---|---|---|---|
| **组织** | 结构良好、模块化 | 大体有组织 | 部分有组织 | 结构较差 |
| **可读性** | 非常清晰易懂 | 清晰 | 基本清晰 | 难以理解 |
| **风格** | 遵循全部规范 | 大体遵循 | 部分遵循 | 无规范 |
| **文档** | 全面 Docstring/注释 | 良好文档 | 基础文档 | 文档较差 |

**评估问题：**
- 是否按逻辑模块组织代码？
- 命名规范是否清晰一致？
- 必要处是否有 Docstring 和注释？
- 是否遵循 PEP 8（Python）或相应语言标准？

**代码质量检查清单：**
- [ ] 合理使用函数与类。
- [ ] 使用类型提示（Python）。
- [ ] 有意义的变量名。
- [ ] 无重复代码。
- [ ] 模块化设计。
- [ ] 单一职责原则。

---

### 3. 基础设施与 DevOps（20 分）

| 标准 | 优秀（18–20） | 良好（16–17） | 合格（14–15） | 需改进（低于 14） |
|---|---|---|---|---|
| **容器化** | 优化的多阶段构建 | 良好 Docker 配置 | 基础容器化 | 容器配置较差或无 |
| **编排** | 生产就绪 K8s 配置 | 良好 K8s 配置 | 基础配置 | 配置较差 |
| **CI/CD** | 自动化流水线正常 | 基础流水线 | 手动部署 | 无自动化 |
| **IaC** | 已实现 Terraform/IaC | 部分 IaC | 少量 IaC | 无 IaC |

**评估问题：**
- Dockerfile 是否优化且安全？
- Kubernetes Manifest 是否生产就绪？
- CI/CD 流水线是否正常？
- 基础设施是否通过代码定义？

**基础设施检查清单：**
- [ ] Dockerfile 多阶段构建。
- [ ] 容器内非 root 用户。
- [ ] 定义资源限制。
- [ ] 实现健康检查。
- [ ] Kubernetes Manifest 有效。
- [ ] CI/CD 流水线正常。

---

### 4. 监控与可观测性（15 分）

| 标准 | 优秀（14–15） | 良好（12–13） | 合格（11） | 需改进（低于 11） |
|---|---|---|---|---|
| **指标** | 全面的 Prometheus 指标 | 良好覆盖 | 基础指标 | 无或极少 |
| **日志** | 结构化且全面 | 良好日志 | 基础日志 | 日志较差 |
| **仪表盘** | 详细 Grafana 仪表盘 | 基础仪表盘 | 少量可视化 | 无 |
| **告警** | 有意义的告警 | 部分告警 | 无告警 | 不适用 |

**评估问题：**
- 是否追踪关键指标？
- 日志是否结构化且有用？
- 是否有 Grafana 仪表盘？
- 告警是否合理配置？

**监控检查清单：**
- [ ] 暴露 Prometheus 指标。
- [ ] 实现结构化日志。
- [ ] 创建 Grafana 仪表盘。
- [ ] 健康端点正常。
- [ ] 配置告警（如要求）。

---

### 5. 测试（10 分）

| 标准 | 优秀（9–10） | 良好（8） | 合格（7） | 需改进（低于 7） |
|---|---|---|---|---|
| **覆盖率** | 超过 80% | 60–80% | 40–60% | 低于 40% |
| **测试质量** | 全面、有意义 | 良好 | 基础 | 较差 |
| **类型** | 单元 + 集成 + E2E | 单元 + 集成 | 仅单元 | 极少测试 |

**评估问题：**
- 是否有自动化测试？
- 是否覆盖核心功能？
- 是否有不同类型测试？
- 是否全部通过？

**测试检查清单：**
- [ ] 有单元测试。
- [ ] 有集成测试（如适用）。
- [ ] 全部测试通过。
- [ ] 合理测试覆盖率。
- [ ] 测试边界情况。
