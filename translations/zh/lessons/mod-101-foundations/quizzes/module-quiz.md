# 答案与解析

## 第一部分：ML 基础设施基础（1–5）

**第 1 题：B**

ML 基础设施工程师构建与维护支持 ML 模型部署和运行的系统，关注基础设施，而非模型训练或研究。

**第 2 题：C**

客户获取是业务职能，不属于技术 ML 生命周期。ML 生命周期包括：数据收集 → 训练 → 评估 → 部署 → 监控 → 重新训练。

**第 3 题：B**

MLOps 在 DevOps 实践基础上增加数据、模型版本管理及模型专用监控。二者均管理代码版本，但 MLOps 还处理数据及模型产物的额外复杂性。

**第 4 题：参考答案**

数据漂移（输入数据分布变化）及概念漂移（输入与输出关系变化）可能导致模型性能随时间退化。使用新数据定期重新训练，有助于保持模型准确且适应当前情况。

**第 5 题：B**

原文认为美国初级 AI 基础设施工程师的典型薪资为 10.7万–23万美元，反映岗位需求与专业技能要求。

## 第二部分：ML 框架（6–10）

**第 6 题：B**

PyTorch 使用动态图（运行时定义），灵活且易调试。TensorFlow 传统上使用静态图（TF 1.x），TF 2.x 增加 Eager Execution，支持动态行为。

**第 7 题：B**

保存状态字典（`model.state_dict()`）更便于移植，原文称体积减少约 50%，并将架构与权重分离。加载时需要模型架构代码。

**第 8 题：B**

`model.eval()` 改变 Dropout（推理时禁用）和 BatchNormalization（使用运行统计量而非批次统计量）等层的行为。遗漏可能导致错误预测。

**第 9 题：A、B、C、E**

正确的优化技术：
- A：量化减小模型体积并加快速度（原文示例缩小 4 倍、加速 2–4 倍）。
- B：TorchScript 编译模型，原文示例推理加速 10–30%。
- C：批量推理相较单次推理加速 3–10 倍（原文示例）。
- E：预热消除首次推理较慢的问题（JIT 编译、CUDA 初始化）。
- D 错误：常规推理不应使用训练模式。

**第 10 题：B**

ONNX（Open Neural Network Exchange）是一种通用模型格式，支持在框架间转换模型（PyTorch ↔ TensorFlow），使用 ONNX Runtime 往往可以加速推理。

**第 12 题：B**

Spot/Preemptible 实例有折扣（原文称最高 90%），但可能在短时间通知后终止（原文示例 30 秒）。适用于批处理、具有检查点的训练及非关键工作负载。

**第 13 题：A、B、D、E**

有效策略：
- A：合理规格避免过度供应。
- B：Spot 实例用于批处理可节省费用，原文称最高 90%。

- E：非工作时间自动关闭以节省费用。
- C 错误：全天运行可能浪费资金，应采用自动扩缩容。

**第 14 题：B**

原文示例 GPU 实例约每小时 1–5 美元：

## 第四部分：模型服务（16–20）

**第 16 题：B**

训练在数小时或数天内使用大型数据集优化准确率；服务使用单样本或小批次，优化低延迟及高吞吐量。

**第 17 题：B**

批量推理一起处理多个请求，利用 GPU 并行处理能力提高利用率，原文称吞吐量提升 3–10 倍。取舍是等待批次填满会增加延迟。

**第 18 题：B**

蓝绿部署中，流量从旧版（蓝）切换至新版（绿）。两个版本同时存在，必要时可以快速回滚。逐步转移流量属于金丝雀部署。

**第 19 题：参考答案**

首次推理可能因 JIT 编译、CUDA Kernel 初始化及内存分配而显著慢于后续推理（原文示例 10–100 倍）。启动时运行模拟推理，有助于使生产请求获得一致、快速的响应。

**第 20 题：C**

影子部署复制生产流量到新模型，但不将其预测返回用户。这样可以用真实数据测试，记录新模型预测进行比较，而不直接改变用户响应。

## 第五部分：Docker（21–25）

**第 21 题：B**

多阶段构建通过构建阶段（包含全部构建工具）和运行阶段（仅包含运行所需内容）减小最终镜像。构建依赖被排除，原文示例减小 50–80%。

**第 22 题：B**

以非 root 用户运行是安全最佳实践。若攻击者利用容器漏洞逃逸，其宿主机权限可能受限；容器中的 root 用户可能获得宿主机 root 权限。

**第 23 题：B、C、E**

原文认为 RUN、COPY、ENV 创建新层并影响缓存：
- COPY 文件变化使缓存失效。
- RUN 命令变化使缓存失效。
- ENV 值变化使缓存失效。
原文称 FROM 与 CMD 不以相同方式创建缓存层。

**第 24 题：B**

CMD 提供运行容器时可覆盖的默认参数，ENTRYPOINT 设置主可执行程序。通常配合使用：ENTRYPOINT 指定命令，CMD 指定默认参数。

示例：
```dockerfile
ENTRYPOINT ["python"]
CMD ["app.py"]
```

运行：`docker run image script.py`（覆盖 CMD）。

**第 25 题：B**

GPU 访问要求：
1. 在宿主机安装 NVIDIA Container Toolkit。
2. 运行时使用 `--gpus` 参数：`docker run --gpus all ...`。
3. 在宿主机安装 NVIDIA 驱动（而非容器中）。

## 第六部分：API 开发（26–30）

**第 26 题：B**

FastAPI 适合 ML 服务：
- 快速：使用 async/await，是较快的 Python 框架之一。
- 自动文档：自动生成 Swagger UI。
- 验证：Pydantic 自动验证请求/响应。
- 类型标注：有助于提前发现错误。

**第 27 题：B**

Pydantic 基于 Python 类型标注提供自动请求/响应验证，验证数据类型、必填字段、取值范围等，并在失败时返回清晰错误。

**第 28 题：参考答案**

400（Bad Request）表示客户端错误——请求格式错误或包含无效数据。可用于验证错误、缺少必填字段、无效输入格式。500（Internal Server Error）表示服务器错误——处理有效请求时出现问题，例如意外异常、数据库错误或服务失败。

**第 29 题：B**

Prometheus 指标提供 API 性能的可观测性：
- 请求速率（请求/秒）。
- 延迟（P50、P95、P99）。
- 错误率。
- 模型专用指标（置信度、预测分布）。
支持监控、告警与容量规划。

**第 30 题：B**

生产环境应向用户返回通用错误信息，避免暴露内部细节，同时在服务端记录详细信息以便调试。不要向用户暴露堆栈追踪、数据库细节或系统信息，以免帮助攻击者。
