   - 使用 BranchPythonOperator。

## 实验 05：端到端 ML 管道

**时长：** 6–8 小时
**难度：** 高级

### 目标
构建完整的生产级 ML 数据管道，综合展示模块 05 的知识。

### 要求
- **编排：** Airflow DAG。
- **数据处理：** 使用 Spark 进行特征工程。
- **流处理：** 使用 Kafka 进行实时推理。
- **质量：** Great Expectations 验证。
- **监控：** Prometheus 指标。
- **版本管理：** 使用 DVC 追踪数据。

### 架构
```
┌─────────────────────────────────────────────────────────┐
│                     Airflow DAG                         │
│                                                          │
│  ┌──────────┐   ┌──────────┐   ┌──────────┐           │
│  │ Extract  │ → │Transform │ → │Validate  │           │
│  │  (API)   │   │ (Spark)  │   │   (GE)   │           │
│  └──────────┘   └──────────┘   └──────────┘           │
│                        ↓                                 │
│                  ┌──────────┐   ┌──────────┐           │
│                  │  Train   │ → │ Register │           │
│                  │  Model   │   │  Model   │           │
│                  └──────────┘   └──────────┘           │
└─────────────────────────────────────────────────────────┘
                          ↓
              ┌───────────────────────┐
              │   Kafka Streaming     │
              │                       │
              │  Events → Features →  │
              │  Model → Predictions  │
              └───────────────────────┘
```

### 阶段 1：批量训练管道（3–4 小时）

**任务：**
1. 搭建项目结构。
2. 创建用于训练的 Airflow DAG。
3. 实现 Spark 特征工程。
4. 添加数据质量验证。
5. 训练并注册模型。
6. 使用 DVC 管理数据版本。

**DAG 结构：**
```python
extract_data >> validate_raw_data >> transform_features >>
validate_features >> train_model >> register_model
```

### 阶段 2：流式推理管道（2–3 小时）

**任务：**
1. 搭建 Kafka 集群。
2. 实现事件生产者。
3. 构建特征工程消费者。
4. 添加模型服务消费者。
5. 将预测结果发送至输出主题。

### 阶段 3：监控与可观测性（1–2 小时）

**任务：**
1. 添加 Prometheus 指标。
2. 创建 Grafana 仪表盘。
3. 实现告警规则。
4. 使用 ELK Stack 配置日志。

### 成功标准
- [ ] 管道处理超过 1 万条记录。
- [ ] 数据质量得分高于 95%。
- [ ] 流处理延迟低于 100ms。
- [ ] 全部测试通过。
- [ ] 监控仪表盘正常工作。
- [ ] 文档完整。
