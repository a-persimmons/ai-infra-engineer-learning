# 练习 11：GPU 成本优化手册

**时长：** 3 小时
**难度：** 中级
**前置条件：** 练习 04（集群管理）、10（共享）

## 目标

针对具有代表性的机器学习服务与训练工作负载，构建结构化成本优化分析：选择哪种 GPU、何时使用 Spot、何时使用预留实例、何时使用 MIG 或独立实例、何时使用按需或无服务器方案。生成相较朴素「H100 全天运行」基线节省至少 40% 成本的建议。

## 为什么重要

GPU 通常是机器学习团队云账单中最大的一项。该项节省 40% 的影响可能超过其他所有项目合计节省 80%。能够可靠完成此类分析的工程师具有较高价值。

## 要求

1. 盘点：列出工作负载及特征（训练或推理、延迟预算、吞吐量、每日使用时长）。
2. GPU 价格表（当前 AWS / GCP / Azure 的按需、Spot、预留实例/CUD 价格）。
3. 对每个工作负载，计算至少三种部署策略的成本，并识别最佳方案。
4. 最终建议矩阵及注释。

## 分步操作

### 步骤 1——工作负载盘点（30 分钟）
定义机器学习平台的五种典型工作负载：
- **W1**：实时推理，平均 100 req/s，峰值 500 req/s，p95 低于 100ms。
- **W2**：夜间批处理推理，四小时处理十亿条记录。
- **W3**：LLM 服务（Mistral-7B），全天运行，平均 50 req/s。
- **W4**：训练，工作日每天八小时，多 GPU。
- **W5**：Notebook / 实验，按需使用，每周 4–12 小时。

### 步骤 2——GPU 价格表（15 分钟）
收集审计当日的实际价格。示例：

| GPU | 按需 美元/小时 | Spot 美元/小时 | 三年 RI 美元/小时 | fp16 TFLOPS | 显存 |
|---|---|---|---|---|---|
| H100 80GB | $4.10 | ~$1.60 | $2.20 | 1979 | 80 GB |
| A100 80GB | $2.90 | ~$1.10 | $1.45 | 624 | 80 GB |
| A100 40GB | $2.10 | ~$0.80 | $1.05 | 312 | 40 GB |
| L40S | $1.50 | ~$0.60 | $0.85 | 363 | 48 GB |
| L4 | $0.90 | ~$0.35 | $0.50 | 121 | 24 GB |
| T4 | $0.35 | ~$0.15 | $0.22 | 65 | 16 GB |

（实际价格变化，请从自己的云服务商获取。）

### 步骤 3——逐工作负载分析（90 分钟）

**W1（实时推理）**——根据延迟预算与稳定需求选择：
- T4 延迟过高，A100 规格过剩，L40S 规格合适。
- 全天运行 → 预留实例更优（原文示例：比按需低约 50%）。
- HPA 在非高峰时段保持最少副本，高峰时段扩容。

**W2（夜间批处理）**——根据吞吐量与成本选择：
- Spot 实例，支持重启的流水线 → 比按需节省 60–70%。
- A100 Spot（1.10 美元/小时）× 4 个实例 × 4 小时 = 17.60 美元；按需为 46.40 美元。

**W3（全天 LLM 服务）**——根据显存与吞吐量选择：
- Mistral-7B fp16 权重约 14GB → 考虑 L40S 或 A100 40GB。
- 全天运行 → 预留实例。
- L40S RI：0.85 美元 × 24 × 30 = 每块 GPU 每月 612 美元；原文比较的按需价格为 0.90 美元/小时，即每月 648 美元。
- A100 40GB RI：1.05 美元 × 24 × 30 = 每月 756 美元（每块 GPU 的性能更高，可能需要更少实例）。

**W4（工作日训练）**——根据互连及 Spot 中断容忍度选择：
- 多 GPU → NVLink 很重要，选择带 NVLink 的 A100 或 H100。
- 长时间训练使用 Spot 风险较高；使用检查点恢复 + Spot，或按需与预留承诺相结合。

**W5（实验）**——根据价格与便利性选择：
- 共享 GPU 的 MIG 分片（原文举例 A100/L40S）、时间切片或每用户 Notebook。
- 对于真正的临时使用，也可以采用无服务器 GPU（Modal、Banana、RunPod）。

### 步骤 4——构建成本模型（30 分钟）
使用电子表格（或 `cost_model.py`）计算每种场景的月度成本。示例：
```python
WORKLOADS = {
    "w1_inference": {
        "gpu": "L40S",
        "instances": {"min": 3, "max": 10, "avg": 4.5},
        "hours_per_day": 24,
        "purchase": "reserved-3yr",
    },
    ...
}
```

### 步骤 5——建议（30 分钟）
编写 `RECOMMENDATIONS.md`，包含：
- 每个工作负载选择的 GPU 与购买方式。
- 估算月度成本（带注释）。
- 与朴素基线相比的节省金额（例如「H100 按需全天运行」）。
- 风险备注（Spot 中断率、预留承诺可能不划算）。

### 步骤 6——拓展：实际实施（取决于访问权限）
如果拥有真实云账号，将推荐配置运行一周，通过 Cost Explorer 获取实际成本，与模型比较。

## 验证

- [ ] 推荐方案总成本不超过朴素「H100 按需全天运行」基线的 60%。
- [ ] 至少一个工作负载使用 Spot、一个使用预留、一个使用无服务器或 MIG。
- [ ] 每项建议引用具体特征（延迟、吞吐量、显存、调度安排）。

## 拓展目标

- 添加 **NCG（NVIDIA Capacity Guarantee）**、Capacity Reservations 与 SP/CUD 对比。
- 构建 **What-if Slider** 仪表盘：改变利用率模式，查看成本影响。
- 实现**自动规格调整**：通过任务查询每个 Pod 过去 30 天的 GPU 利用率，并建议降低规格。

## 常见陷阱

- **预留实例假设需求稳定**——为波动工作负载购买三年 RI 可能亏损。计算盈亏平衡利用率（原文举例：一年 RI 约 60% 的小时数，三年 RI 约 75%）。
- **Spot 中断提高实际成本**——原文建议为重跑预留 20–30% 开销。
- **TFLOPS 不等于延迟**——TFLOPS 高两倍的 GPU 不一定使单请求推理快两倍；吞吐量与延迟的扩展规律不同。
- **隐藏费用**——存储（快照、EBS）、网络出站、NAT、ALB。始终计入这些费用。
