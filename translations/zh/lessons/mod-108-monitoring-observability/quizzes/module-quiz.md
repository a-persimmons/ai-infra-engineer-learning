## 第八部分：实践场景（简答）

### 场景 1：高延迟排查

**情况：** ML 模型服务端点的 P99 延迟突然从 100ms 增至 2,000ms。

**问题：** 列出诊断问题时要检查的五种指标/日志/Trace，并解释原因。

**参考答案：**
1. **GPU 利用率**（`gpu_utilization`）：检查 GPU 是否饱和（超过 95%）。
2. **GPU 显存**（`gpu_memory_used/total`）：检查显存耗尽。
3. **批大小分布**（`histogram_quantile(batch_size)`）：异常大的批次可能导致处理较慢。
4. **错误日志**（搜索 ERROR 或 OOM）：识别崩溃或显存错误。
5. **Trace**（过滤高耗时链路）：查看管道哪个阶段较慢（预处理、推理、后处理）。
6. **近期部署**（`kubectl get events`）：检查是否部署了新版本。

### 场景 2：设计告警

**情况：** 为每秒处理 10,000 笔交易的新欺诈检测服务搭建监控。

**问题：** 设计三条关键告警（指定指标、阈值、持续时间、严重级别）。

**参考答案：**

1. **高错误率**
   - 指标：`(sum(rate(predictions_total{status="error"}[5m])) / sum(rate(predictions_total[5m]))) * 100`
   - 阈值：超过 5%。
   - 持续时间：`for: 5m`。
   - 严重级别：Critical。
   - 原因：超过 5% 的错误影响许多用户。

2. **模型准确率下降**
   - 指标：`model_accuracy{dataset="validation"}`。
   - 阈值：低于 0.90。
   - 持续时间：`for: 10m`。
   - 严重级别：Critical。
   - 原因：准确率低于 90% 表示模型表现不足。

3. **预测吞吐量过低**
   - 指标：`sum(rate(predictions_total[5m]))`。
   - 阈值：低于 5,000（预期的 50%）。
   - 持续时间：`for: 5m`。
   - 严重级别：Warning。
   - 原因：吞吐量显著下降可能表明扩缩容问题。

### 场景 3：数据漂移检测

**情况：** 模型准确率在过去一周从 95% 降至 88%，怀疑存在数据漂移。

**问题：** 描述确认并量化漂移的步骤。

**参考答案：**

1. **采集参考数据：** 获取训练集或上一次已知正常时期的特征分布。
2. **采集当前数据：** 获取近期生产推理数据（过去一周）。
3. **按特征计算漂移指标：**
   - 数值特征：Kolmogorov-Smirnov（KS）检验、PSI。
   - 类别特征：卡方检验。
4. **识别发生漂移的特征：**
   ```python
   # PSI > 0.25 = significant drift
   ```

5. **可视化分布：**
   - 绘制参考与当前分布的直方图。
   - 在 Grafana 创建漂移仪表盘。
6. **与准确率关联：**
   - 检查漂移最大的特征是否与准确率下降相关。
7. **根因分析：**

8. **行动：**
