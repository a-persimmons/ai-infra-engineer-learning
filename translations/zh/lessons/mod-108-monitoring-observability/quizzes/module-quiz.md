## 第 8 部分：实践场景（简答）

### 场景 1：排查高延迟

**情况：** ML 模型服务端点的 P99 延迟突然从 100ms 上升到 2000ms。

**问题：** 列出会检查的 5 项指标、日志或追踪，并解释原因。

**参考答案：**
1. **GPU 利用率**（gpu_utilization）：检查 GPU 是否饱和（>95%）
2. **GPU 显存**（gpu_memory_used/total）：检查显存耗尽
3. **批次大小分布**（histogram_quantile(batch_size)）：异常大的批次会减慢处理
4. **错误日志**（搜索 ERROR 或 OOM）：识别崩溃或内存错误
5. **Trace**（筛选长耗时）：确认流水线哪一阶段较慢（预处理、推理、后处理）
6. **最近部署**（kubectl get events）：检查是否部署了新版本

### 场景 2：设计告警

**情况：** 为每秒处理 10,000 笔交易的新欺诈检测 ML 服务配置监控。

**问题：** 设计 3 项关键告警（说明指标、阈值、持续时间及严重级别）。

**参考答案：**

1. **高错误率**
   - 指标：`(sum(rate(predictions_total{status="error"}[5m])) / sum(rate(predictions_total[5m]))) * 100`
   - 阈值：`> 5%`
   - 持续时间：`for: 5m`
   - 严重级别：Critical
   - 原因：超过 5% 的错误会影响许多用户

2. **模型准确率下降**
   - 指标：`model_accuracy{dataset="validation"}`
   - 阈值：`< 0.90`
   - 持续时间：`for: 10m`
   - 严重级别：Critical
   - 原因：准确率低于 90% 表明模型表现不足

3. **预测吞吐量过低**
   - 指标：`sum(rate(predictions_total[5m]))`
   - 阈值：`< 5000`（预期的 50%）
   - 持续时间：`for: 5m`
   - 严重级别：Warning
   - 原因：吞吐量显著下降可能意味着扩容问题

### 场景 3：数据漂移检测

**情况：** 模型准确率在过去一周从 95% 降至 88%，怀疑存在数据漂移。

**问题：** 描述确认并量化漂移的步骤。

**参考答案：**

1. **收集参考数据：** 获取训练集或上次正常时期的特征分布。
2. **收集当前数据：** 获取最近一周生产推理数据。
3. **逐特征计算漂移指标：**
   - 数值特征：Kolmogorov-Smirnov（KS）检验、PSI
   - 类别特征：卡方检验
4. **识别漂移特征：**
   ```python
   # PSI > 0.25 = significant drift
   # KS test p-value < 0.05 = drift detected
   ```

5. **可视化分布：**
   - 绘制参考分布与当前分布的直方图
   - 创建 Grafana 漂移仪表盘
6. **关联准确率：**
   - 检查漂移最显著的特征是否与准确率下降相关
7. **根因分析：**
   - 检查数据流水线变更日志
   - 验证特征工程逻辑
   - 检查季节性或外部事件
8. **采取行动：**
   - 使用近期数据重新训练模型
   - 更新特征工程
   - 建立持续漂移监控
